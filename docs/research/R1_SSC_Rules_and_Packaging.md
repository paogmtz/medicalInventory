## 1. Hard Requirements Checklist

### 1.1 Submission Format

| Requirement | Detail |
|---|---|
| **File format** | App Playground (`.swiftpm`) inside a ZIP file |
| **ZIP size limit** | <= 25 MB |
| **Experience duration** | <= 3 minutes |
| **Network dependency** | NONE -- must work 100% offline; all resources must be bundled locally |
| **Compatible tools** | Swift Playgrounds 4.6+ **or** Xcode 26+ |
| **Language** | All content must be in **English** |
| **Submissions per person** | Exactly **one** app playground |

> **Nota para la desarrolladora:** El archivo final que subes es un ZIP que contiene un unico .swiftpm. No un .xcodeproj, no un .playground -- solo .swiftpm. Todo recurso (imagenes, sonidos, modelos CoreML) debe estar DENTRO del ZIP. 25 MB es el limite total.

### 1.2 Individual Work Policy

- The submission **must be created by you as an individual** or be a Swift Playground template modified entirely by you as an individual.
- **Group work will NOT be considered.**
- Third-party open source code, public domain images, and sounds **may** be included, but you must:
  - Comply with all applicable licensing terms and copyright obligations.
  - Provide credit and an **explanation of why** each third-party resource was used.
- Apple takes plagiarism very seriously. Plagiarized works, **including design aspects**, will not be considered and may disqualify you from future Challenges.

### 1.3 AI Disclosure Requirements

**Policy:** AI tools may be used to assist with specific tasks of your project, **provided that all usage is fully disclosed.**

**What Apple expects you to demonstrate despite AI use:**
- Significant individual contributions
- Technical understanding of your app playground
- Problem-solving skills
- Creativity
- User experience and design judgment
- Appropriate use of tools and technologies

**Where to disclose:** The submission form includes an essay question (approx. 500 words max) that asks you to describe the user experience and frameworks you used. Within that response, **if you used AI tools, you must provide details about how and why they were used.**

**Important:** Essay answers on the submission form must be **written by you personally** -- not generated by AI.

> **Nota para la desarrolladora:** Apple permite usar herramientas de IA (ChatGPT, Copilot, etc.) pero DEBES declarar exactamente como las usaste y por que. Los ensayos del formulario deben ser escritos por ti, no generados por IA. La clave es demostrar que TU entiendes el codigo y las decisiones tecnicas.

### 1.4 Automatic Disqualification Triggers

Your submission will be disqualified if:

1. The app playground **does not function** during judging
2. It was **not built by you** or was built by more than one person
3. It contains **plagiarized work** (including design aspects)
4. It **requires sign-in** to use
5. It contains **tracking/analytics code** meant to identify or track judges
6. It is the **same app playground submitted previously** with minimal or no changes
7. You submit **multiple app playgrounds** (only one allowed)
8. Any part of the submission is **untrue, plagiarized, or fabricated**
9. There is **misappropriation of intellectual property**, open source content, music, photos, or artwork

## 2. Packaging Details

### 2.1 How to Create a Proper .swiftpm Project

#### In Xcode 26:
```
File > New > Project > iOS > App Playground
```

#### In Swift Playgrounds 4.6 (iPad or Mac):
```
Open Swift Playground > Create New App
```

**CRITICAL:** You must select **"App Playground"** (also called "Swift Playgrounds App"), NOT a standard Xcode project, NOT a `.playground` file. The result must be a `.swiftpm` package.

### 2.2 .swiftpm Internal Structure

A `.swiftpm` file is actually a **folder** (macOS displays it as a single file). Its internal structure:

```
MyApp.swiftpm/
|-- Package.swift              <-- Manifest (defines targets, products, resources)
|-- MyApp.swift                <-- App entry point (conforms to App protocol)
|-- ContentView.swift          <-- Main view
|-- [other .swift files]       <-- Additional source files
|-- Resources/                 <-- Images, sounds, CoreML models, data files
|   |-- Assets.xcassets/       <-- Asset catalog (app icon, colors, images)
|   |-- model.mlmodel          <-- (example) CoreML model
|   |-- data.json              <-- (example) local data
|-- .swiftpm/                  <-- Xcode workspace metadata (auto-generated)
|   |-- xcode/
|       |-- package.xcworkspace/
```

#### The Package.swift Manifest

The default `Package.swift` for an App Playground uses the `AppleProductTypes` framework and defines an `.iOSApplication` product:

```swift
// swift-tools-version: 5.9
import PackageDescription
import AppleProductTypes

let package = Package(
    name: "MyApp",
    platforms: [
        .iOS("18.0")
    ],
    products: [
        .iOSApplication(
            name: "MyApp",
            targets: ["AppModule"],
            bundleIdentifier: "com.example.MyApp",
            // ...
        )
    ],
    targets: [
        .executableTarget(
            name: "AppModule",
            path: ".",
            resources: [
                .process("Resources")
            ]
        )
    ]
)
```

**Key notes about `Package.swift`:**
- Swift tools version defaults to **5.9** even in Swift Playgrounds 4.6 (which uses the Swift 6 compiler in Swift 5 language mode).
- The default target path is `"."` (root), meaning source files live at the project root, not in a `Sources/` folder.
- You can optionally restructure into `Sources/AppModule/` but must update the path accordingly.
- Resources are declared via `.process("Resources")` in the target definition.

### 2.3 What Files/Structure Must Be in the ZIP

The ZIP must contain:
1. **One `.swiftpm` folder** (the entire app playground package)
2. All source code (`.swift` files)
3. All resources (images, sounds, data, models) inside the package
4. The `Package.swift` manifest
5. Asset catalogs (`.xcassets`) if used

**The ZIP must NOT contain:**
- `.DS_Store` files (macOS metadata -- clean these out)
- `xcuserdata/` folders
- Any files that reference network endpoints
- Derived data or build artifacts
- External framework binaries (not supported; include source code instead)

### 2.4 How to Create the ZIP

```bash
# Navigate to the directory CONTAINING your .swiftpm
cd /path/to/parent/directory

# Clean macOS metadata first
find . -name ".DS_Store" -delete
find . -name "xcuserdata" -type d -exec rm -rf {} +

# Create ZIP
zip -r MyApp.zip MyApp.swiftpm -x "*.DS_Store" -x "*xcuserdata*"

# Verify size (must be <= 25 MB)
ls -lh MyApp.zip
```

> **Nota:** Tambien puedes crear el ZIP desde Finder: click derecho sobre el .swiftpm > "Comprimir". Pero el metodo de terminal es mas limpio porque excluye archivos basura.

### 2.5 Common Pitfalls That Cause Rejection

| Pitfall | Description |
|---|---|
| **Wrong project type** | Creating an Xcode Project (`.xcodeproj`) instead of an App Playground (`.swiftpm`). This is the #1 mistake. |
| **Network dependency** | Any `URLSession` call, remote API, or Swift Package dependency from GitHub will FAIL offline. |
| **ZIP too large** | Over 25 MB. Compress images aggressively. Use HEIC or optimized PNG. Reduce CoreML model size. |
| **Builds in Xcode but not in Swift Playgrounds** | Some code (especially Metal shaders with `.metal` files, or newer APIs) compiles in Xcode but fails in Swift Playgrounds. Always test in BOTH. |
| **Missing resources** | Resources not declared in `Package.swift` or not included in the `Resources/` folder won't be bundled. |
| **Duration exceeds 3 minutes** | Judges will only spend up to 3 minutes. If your core experience is not visible in that window, it may be judged incomplete. |
| **Content not in English** | All UI text, comments, and essay responses must be in English. |
| **Requires sign-in** | Any authentication gate will cause disqualification. |
| **App crashes on launch** | If the app does not function during judging, it is automatically disqualified. Test thoroughly. |
| **External SPM dependencies** | Remote Swift Package Manager dependencies require internet to resolve. They will fail in the offline judging environment. |
| **Core ML model not compiled** | If using Core ML, the `.mlmodel` must be properly included. In some cases, you need to compile it to `.mlmodelc` in Xcode first before including it in the Playground project. |

### 2.6 How to Verify the Package Works

1. **Test in Swift Playgrounds on iPad** (primary judging device):
   - Transfer the `.swiftpm` via AirDrop, Files, or iCloud
   - Open it in Swift Playgrounds 4.6
   - Confirm it builds and runs without errors

2. **Test in Swift Playgrounds on Mac:**
   - Open the `.swiftpm` directly in Swift Playgrounds for Mac
   - Confirm all views render and interactions work

3. **Test the ZIP itself:**
   - Unzip on a different machine or location
   - Open the extracted `.swiftpm` in Swift Playgrounds
   - Confirm nothing is broken (missing resources, failed imports)

4. **Test offline:**
   - Enable Airplane Mode on the device
   - Launch the app and confirm full functionality

5. **Time your experience:**
   - Use a stopwatch and confirm the full experience is under 3 minutes

6. **Right-click > Show Package Contents** (on Mac):
   - Verify all `.swift` files are present
   - Verify `Resources/` contains all expected assets
   - Verify `Package.swift` is present and valid

### 3.2 Written Components (Submission Form)

The submission form requires several written responses. Based on official Apple Developer sessions and community reports, the key fields are:

#### Required Written Responses:

1. **App Name**
   - Clear, concise, memorable
   - Should reflect the core function or theme

2. **One-Sentence Description** (~50 words max)
   - Elevator pitch: what does your app do and what problem does it solve?
   - Be concise and avoid vague language.

3. **User Experience & Technology Choices** (~500 words max)
   - Describe the user experience you aimed for
   - Explain **why** you chose the frameworks you used
   - **If you used AI tools, provide details about how and why they were used** (this is the AI disclosure field)
   - Mention non-code technologies used (audio tools, Create ML, etc.)
   - Explain how your technology choices enhanced the user experience

4. **Community Impact / Beyond the Swift Student Challenge**
   - Describe how you've used coding skills to support your community or an organization
   - Specific examples with measurable impact
   - Tutoring, hackathons, coding clubs, apps for school organizations, etc.

5. **App Store Experience** (Optional)
   - If you have published apps, summarize their functionality
   - Mention skills learned through the publication process

6. **Comments** (Optional)
   - Additional context, challenges overcome, unique circumstances
   - Limited hardware access, personal story, etc.

#### Required Documents:

- **Proof of enrollment:** PDF, PNG, or JPEG of current class schedule or proof of enrollment showing:
  - Your name
  - Organization/school name
  - Valid dates at time of submission
- **Contact information** for your dean or principal

### 3.3 How to Structure the AI Disclosure

The AI disclosure lives within the "User Experience & Technology Choices" essay (500 words max). Structure it clearly:

**Recommended structure within the essay:**

```
[1. User Experience Description -- ~200 words]
Describe the experience you designed and why.

[2. Framework Choices -- ~150 words]
Explain which Apple frameworks you used (SwiftUI, SpriteKit, CoreML, etc.) and why.

[3. AI Tools Disclosure -- ~150 words]
If applicable, clearly state:
- WHICH AI tools you used (e.g., "Claude", "ChatGPT", "GitHub Copilot")
- WHAT specific tasks you used them for (e.g., "debugging a SpriteKit collision issue",
  "generating placeholder text for prototyping", "learning about Core Animation APIs")
- WHY you chose to use AI for those specific tasks
- HOW you verified/modified/understood the output before incorporating it
- WHAT you personally contributed beyond the AI-assisted portions
```

**Example AI disclosure paragraph:**

> "During development, I used Claude to help me understand the Core Motion API for accelerometer data, and to debug a specific issue with SKPhysicsBody collision detection. I reviewed all suggested code, modified it to fit my architecture, and tested edge cases manually. The app's concept, design, user experience flow, all SwiftUI views, and the medical inventory logic were entirely my own work."

> **Nota:** Si usaste IA para algo -- cualquier cosa -- declaralo. Es mejor ser transparente. Apple no penaliza por usar IA; penaliza por NO declararlo. Manten la seccion breve, honesta, y demuestra que entiendes todo el codigo de tu proyecto.

### 4.2 What APIs Work Offline

**Fully offline-capable (safe to use):**
- SwiftUI (all of it)
- UIKit (all of it)
- SpriteKit, SceneKit, Metal
- Core ML (inference with bundled models)
- Vision (on-device analysis)
- Core Motion (accelerometer, gyroscope)
- Core Haptics
- PencilKit
- AVFoundation (for bundled audio/video, camera capture)
- Core Data, SQLite3
- Core Graphics, Core Image, Core Animation
- Combine
- GameplayKit
- Natural Language
- Accessibility
- ARKit / RealityKit

**NOT offline-capable (avoid or use with caution):**
- URLSession / any HTTP networking
- MapKit (map tiles require internet; bundled data possible but complex)
- CloudKit
- Remote Swift Package dependencies
- Sign in with Apple / any authentication service
- StoreKit (requires App Store connection)
- Any API that fetches remote resources

> **Nota:** La regla de oro: si tu funcion necesita internet para funcionar, NO la uses. Toda la experiencia de la app se juzga offline en un iPad.

### 4.3 Storage / Sandbox Limitations

- **No Info.plist:** Swift Playgrounds does not use a traditional Info.plist. Capabilities are declared via the Capabilities control in Swift Playgrounds or through Package.swift.
- **No App Extensions:** App extensions (widgets, keyboard extensions, share extensions, etc.) are not supported.
- **No Unit Testing:** XCTest framework is not available in Swift Playgrounds. No unit test or UI test support.
- **No linking external compiled frameworks:** You cannot include pre-compiled `.framework` or `.xcframework` binaries. All third-party code must be included as **source files**.
- **Limited build settings:** Cannot customize Xcode build settings. All products and targets must support the same baseline OS version.
- **No Objective-C bridging header:** Swift Playgrounds doesn't support Objective-C bridging headers.
- **File system sandbox:** The app runs in the standard iOS sandbox. You can read/write to the app's own container but not to arbitrary file system locations.
- **25 MB total ZIP:** This is your total budget for all code, assets, models, sounds, and images.

### 4.4 Camera / Photo Picker Availability

#### Camera Access
- **Available:** Yes, via `AVFoundation` APIs (`AVCaptureSession`, etc.)
- Camera access has been available since Swift Playgrounds 2.0 (iOS 11+)
- Works on iPad with front and rear cameras
- The app playground must declare camera capability
- **Important for SSC:** Camera features work but judges may be testing on devices in various orientations. Ensure graceful handling.

#### Photo Picker
- **Available:** Yes, via `PhotosUI` framework (`PhotosPicker` in SwiftUI) or `UIImagePickerController`
- Requires declaring photo library access capability
- Photos selected by the user are available offline (they are on-device)
- **Important for SSC:** If your app depends on user-selected photos, provide fallback content or bundled sample images so judges can experience the full app without needing specific photos.

#### Capability Declaration
In Swift Playgrounds, you add capabilities through the **Capabilities** interface (gear icon > Capabilities). Available capabilities include approximately 20 options:
- Camera
- Microphone
- Photo Library
- Location
- Bluetooth
- Face ID
- Contacts
- Calendars
- Reminders
- Motion & Fitness
- Media Library
- HomeKit
- Health
- NFC
- Nearby Interaction
- And others

### 4.5 Specific Considerations for a Medical Inventory App

Given this project is a medical inventory application, here are targeted constraints to keep in mind:

- **Data storage:** Use Core Data, SwiftData, or SQLite3 for inventory persistence. All data must be local.
- **No server/cloud sync:** No Firebase, no REST APIs, no CloudKit during judging.
- **Pre-loaded sample data:** Include realistic sample inventory data so judges see a populated app immediately. Do not rely on judges entering data manually within 3 minutes.
- **Barcode scanning:** If using barcode/QR scanning, it requires camera access via AVFoundation or Vision. Works offline.
- **Image assets:** Compress medical item images to stay within 25 MB. Consider using SF Symbols where possible to save space.
- **Accessibility:** Medical apps benefit greatly from strong accessibility (VoiceOver, Dynamic Type). This also scores well for "inclusivity" judging criterion.
- **Localization note:** All UI must be in English for judging, even though this is for medical use in a Spanish-speaking context.

> **Nota para la desarrolladora:** Para la app de inventario medico, precarga datos de ejemplo realistas. Los jueces solo tienen 3 minutos -- no van a crear items manualmente. Muestra la funcionalidad completa desde el primer momento. Usa SF Symbols para iconos medicos y ahorra espacio en el ZIP.
